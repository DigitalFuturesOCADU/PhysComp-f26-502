Workshop Goal

Create your first dynamically controlled visuals on the LED matrix — using sensor input to drive what appears on screen. Focus on building a clear, intentional relationship between the type of input and the output it controls.

Resources
  • Arduino UNO R4 WiFi
  • HC-SR04 distance sensor + 4 plug/header jumper wires
  • Pressure sensor kit — Velostat, copper tape, conductive materials (get from Nick)
  • Alligator clip jumper wires
  • 10kΩ resistor (for pressure sensor voltage divider)
  • Class 06 Notes — Sensor examples and code patterns
  • TinyFilmFestival Documentation
Activity

Starting from the examples covered in class, create a simple sensor-driven interaction for both the distance sensor and the pressure sensor. You can use the animation method, canvas method, or both — but the visuals should be different for each sensor. Simple is fine. A clear connection between input and output is what matters.

Part 1 — Distance Sensor Interaction

  1. Wire up the HC-SR04 and run the Quick Serial Test to confirm it works.
  2. Write a one-sentence description of your interaction: "When I ______, the screen shows ______."
  3. Write out the steps in plain language (pseudo code) — what does the code need to read, translate, and draw?
  4. Build the simplest version of the code that achieves the interaction.
  5. Make it better — adjust thresholds, tweak the mapping, refine the visual.

Part 2 — Pressure Sensor Interaction

  1. Build your custom FSR and wire it with the voltage divider circuit. Run the Quick Serial Test to confirm it reads pressure changes.
  2. Write a one-sentence description of your interaction: "When I ______, the screen shows ______."
  3. Write out the steps in plain language (pseudo code) — what does the code need to read, translate, and draw?
  4. Build the simplest version of the code that achieves the interaction.
  5. Make it better — adjust thresholds, tweak the mapping, refine the visual.

Tip: Use Serial Monitor to find your real sensor values before writing screen code. Don't guess — measure first, code second.
